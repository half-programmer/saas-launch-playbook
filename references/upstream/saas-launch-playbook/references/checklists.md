# Checklists：上线前 / 上线周 / 上线后

## 一、启动前检查总表（分四类）

### 产品
- [ ] 核心闭环：陌生人不经帮助能自己走到核心价值
- [ ] 注册/登录稳定（Google OAuth 起步即可），桌面 + 移动端都测过
- [ ] 支付用**真实卡**跑通过全流程（含 webhook、失败重试、收据邮件）
- [ ] 上手引导：示例数据或引导式首次操作，time-to-value < 5 分钟
- [ ] 事务邮件不进垃圾箱（查 spam score）
- [ ] 页面速度达标
- [ ] 10–50 人结构化内测已跑完，反馈收敛在一个表单/一个渠道
- [ ] 上线物料备齐：截图、30–60 秒演示视频/GIF、一段话介绍、一页纸介绍、基础帮助文档

### 法务
- [ ] 隐私政策、服务条款已上线
- [ ] Cookie 同意（如目标市场要求）
- [ ] 公司主体 / 收款主体已定

### 营销
- [ ] 着陆页 + 等待名单已上线（带一个筛选问题："你现在最大的麻烦是什么？"）
- [ ] 定价页已上线（含一个显眼的主计划、月付/年付、"联系我们"逃生口）
- [ ] 楔子一句话已通过"换 logo 测试"，并找 10 个访谈对象验证过理解一致
- [ ] 公开建造已持续 ≥2 周（不断更）
- [ ] ICP 所在的 2–3 个社区已混熟（先贡献再索取，读过各社区自推广规则）
- [ ] BetaList 已提交
- [ ] Product Hunt 物料定稿：缩略图、60 字符内标语、演示视频、maker comment（讲创始故事 + 提一个真问题）
- [ ] 目录/平台电子表格建好：URL、登录状态、提交状态
- [ ] 关键人 outreach 名单 + 个性化消息写好（内测用户、访谈对象、等待名单、友好创始人）

### 数据
- [ ] 事件追踪已接（PostHog / Plausible / Mixpanel 二选一以上）
- [ ] 错误监控已接
- [ ] 四个早期指标的看板就绪：访客→注册、注册→激活、激活→付费、NRR
- [ ] 能回答"每个付费用户从哪个渠道来"

## 二、上线前一周

- [ ] Product Hunt 定在周二 12:01 AM Pacific（或守不住评论区就选安静的周日），有人全天守 thread
- [ ] 等待名单软启动：提前几天开放，让他们先踩 bug
- [ ] outreach 消息排好发送时间（上线日最初几小时发出）
- [ ] 跑一遍 no-go checklist（下）
- [ ] 准备好"修好了谢谢"的话术模板和快速发版通道

## 三、No-Go Checklist（上线日硬门槛，任一不过就推迟）

- [ ] 注册流程端到端可用
- [ ] 支付流程用真卡可用
- [ ] 核心功能可用
- [ ] 事务邮件正常送达、不进垃圾箱
- [ ] 法务页面可访问
- [ ] 找一个**不是你**的人在桌面和手机上各走一遍

## 四、上线后 8 周节奏

| 周 | 动作 |
|---|---|
| +1 | 小平台第二波（Uneed / Microlaunch / Fazier / Peerlist…）；24 小时内回复一切；triage 修阻塞项 |
| +2 | 两周内收齐第一批 testimonial（两句话，讲用户达成了什么）；修 onboarding 第一轮 |
| +3 ~ +4 | 目录提交第一批；第一个案例写出来；每周看指标，定位断层在 seen / signup / activation / paid 哪一环 |
| +5 ~ +6 | 留存系统：失败支付挽回、唤醒邮件、应用内 nudge；启动对比页/SEO |
| +7 ~ +8 | 复盘哪个渠道产出了付费用户，决定加倍方向；重访定价（没人嫌贵 = 定便宜了） |

## 五、Triage 规则（上线前写好，贴墙上）

- **当天修**：阻塞注册、阻塞支付、阻塞核心动作。
- **排期修**：其他一切。
- 上线第三天你会很累，这张纸替你做决定。
